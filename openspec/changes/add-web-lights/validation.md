# Validation

## 驗證範圍

- 對應變更：add-web-lights
- 驗證環境：本機 Vite dev（5173）；Playwright 1.62.1 Chromium（`--use-angle=metal`，Apple M2）；桌機 1280×800、手機 390×844（touch, DPR 2）

## 功能驗證

- [x] 游標光跟著滑鼠：(-1.27, 1.95) → (1.41, 0.87)
- [x] 點擊換色：首頁游標光 0 → 1；點「開始」只捲動不換色；點光源段 RGB 換組
- [x] 捲到 1.5 倍 → RGB 0.5、聚光燈 0.5（交替淡入淡出）
- [x] 聚光燈照射點跟著滑鼠移動；面光源 x 跟著滑鼠（-1.28 → 1.15）；面光源點擊切冷白
- [x] 導覽點第 5 個 → 霓虹段權重 1；點擊換青色
- [x] reduced motion：權重立即到位
- [x] 手機：不開陰影、雕塑在上半部、無水平捲動

## 視覺驗證

- 6 段截圖：游標暖光、RGB 混光、聚光燈光圈與陰影、暖白柔光面板與鉻金屬方形反光、霓虹光環與追逐燈、範例清單（燈光調暗當背景）

- Apple M2：60 FPS

## 回歸驗證

- `npm run build` 產出 8 頁；`web.html` 範例清單新增「燈光互動網頁」卡片，其他頁面未修改

## 問題與修正紀錄

- 聚光燈段與最後一段整個畫面全黑
  - 發現方式：截圖；關閉光束後正常、關閉 Bloom 後也正常 → 光束 Shader 產生 NaN，被 Bloom 模糊擴散到全畫面
  - 原因：`pow(0.0, 1.4)` 在 Apple Metal 會得到 NaN
  - 修正：底數 `max(vAlong, 0.0001)`；已重新驗證
- 面光源面板太近太亮佔滿上半部 → 縮小面板、往後放、降低面板亮度
- 聚光燈照到雕塑時過曝 → 強度 130 → 55；照射範圍限制在展台附近
- 其他段落看得到暗紅霓虹環 → 關閉時底亮度 0.06 → 0.015
- 最後一段燈光蓋過卡片文字 → 該段權重調低、關閉面光源

## 結論

- 是否通過：是
- 已知限制或風險：RectAreaLight 查表資料使頁面 JS 較大（與 market 共用 chunk）
- 後續追蹤事項：可加入「混光」段讓使用者同時調整多種燈
