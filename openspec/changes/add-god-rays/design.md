# Design

- 全螢幕四邊形、`AdditiveBlending`、不測不寫深度、`toneMapped: false`，在 `foregroundBlur.render()` 之後畫：只會讓畫面變亮，不會遮住東西。
- 光束方向固定：從「直直往下」往右轉 `angleDegrees`（預設 38°），所有光束平行。
- 橫跨光束的座標 `dot(p, across)` × 密度，兩層 1D 平滑雜訊（粗＋細、各自往不同方向飄）決定哪裡有光；先用 smoothstep 拉開對比再依銳利度取次方（直接取次方會整片太暗，疊在明亮天空上看不出來）。
- 從左上角（`originX`）進來最亮：沿光的方向走越遠越淡（`reach`），橫向也稍微淡一點；整體慢慢呼吸。
- 畫面座標先乘寬高比，斜度不會被視窗比例拉扁。
- 曾先做成「從畫面上方一點放射出去的扇形光」，使用者要求改成平行斜光後改掉；也曾誤做成菠蘿麵包上方的光錐，已還原。

## 第二輪：避開彩虹

- 「從左上角最亮」改成「入射窗口」：每個像素沿著光束往回推，算出光是從畫面上緣哪裡射進來的（entryX）；只有從 `originX`（預設 0.55）往右 `width`（0.9）那段射進來的才有光，沿著光的方向往右下淡出。
- 舊作法只看「離最亮點多遠」，平行光的上游（最亮點左上方、彩虹那一帶）也會被照到，左上角疊成一片偏白的霧。

## 第三輪：視窗拉寬不移動

- 畫面座標改成「以畫面中心為 x 原點、以畫面高度為單位」；`originX` 也改成離畫面中心多遠（畫面高度的倍數，負 = 左），預設 -0.72（≈ 使用者在 1440×820 設的 0.09）。
- 舊作法以「畫面寬度的比例」算，視窗拉寬時起點和整片光紋都會滑動；綠球永遠在畫面中間，改成以中心為準後，拉寬只是兩側多出空間。
- 驗證：同高度 1200、1800 寬，各取以中心為準的同一塊區域並排，光紋位置一致。
